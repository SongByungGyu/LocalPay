# 02. 아키텍처 및 교체 지점

## 핵심 원칙

1. **지도 SDK 은닉** — 좌표는 원시 `Double(latitude, longitude)` 로만 보관. `CLLocationCoordinate2D` 는 computed property 로만 노출. `MapKit` 은 오직 `MapHomeView` 안에서만 import.
2. **Repository 단일 접점** — 모든 매장 데이터 접근은 `MerchantRepository` protocol 을 통해서만 이루어짐. 구현체 교체만으로 로컬 → 원격 전환 가능.
3. **Store 는 화면-무관 상태** — `FavoritesStore` · `ReviewsStore` 는 View 트리와 무관한 순수 상태 + 영속화 계층. 여러 화면에서 Environment 로 공유.
4. **DEMO 표시 강제** — 모든 임의 데이터(잔액, 최근 결제, 지역화폐 혜택)에는 DEMO 뱃지가 반드시 붙는다. 실 데이터 오인 방지 (CLAUDE.md §12).

## 교체 지점 매트릭스

각 실 데이터 · SDK 를 붙일 때 "정확히 어디를 만들거나 바꾸는가" 를 다음 표로 정리했습니다.
상세는 `../API_INTEGRATION.md` 참조.

| 붙이려는 대상 | 신규 파일 | 기존 파일 변경 | 도메인 모델 변경 |
|---|---|---|---|
| **온누리 · 지역화폐 매장 목록** (공공데이터/API) | `Data/Repository/RemoteMerchantRepository.swift` | ViewModel `init` 의 기본 주입값만 스왑 | ❌ (Codable 이미 채택) |
| **Kakao Local** (좌표·주소 보정) | `Utilities/PlaceEnricher.swift` | `RemoteMerchantRepository` 내부에서 호출 | ❌ |
| **Kakao Map SDK** (지도 렌더링) | `Features/Map/KakaoMapView.swift` (UIViewRepresentable), `Features/Map/MapProviderAdapters.swift` | `MapHomeView` 안에서 조건부 스왑 | ❌ (`MapMarkerModel`/`MapRegion` 그대로) |
| **개인 상품권 · 지역화폐 잔액** | `Data/Wallet/WalletService.swift` (+ 각 상품권별 구현체) | `Features/MyPage/BalanceCard.swift` — hardcoded `demoBalance` 대신 서비스 값 바인딩 | ❌ |
| **회원가입 · 로그인** | `Features/Auth/*` | `LocalPayApp` 에서 세션 상태 라우팅 | 부분적 (User 도메인 신설) |

## 상태 관리 요약

| 상태 | 도구 | 위치 | 영속 |
|---|---|---|---|
| 지도 필터 · 선택 마커 · 카메라 | `@State` + `MapHomeViewModel` (`@Observable`) | 화면 로컬 | ❌ |
| 검색 결과 · 정렬 · 쿼리 | `@Observable SearchViewModel` | 화면 로컬 | ❌ |
| 즐겨찾기 ID 집합 | `@Observable FavoritesStore` | Environment (앱 전역) | ✅ UserDefaults |
| 사용자 후기 | `@Observable ReviewsStore` | Environment (앱 전역) | ✅ UserDefaults |
| 위치 권한 · 마지막 좌표 | `@Observable LocationService` | 화면 로컬 (MapHome) | ❌ (매 세션 요청) |
